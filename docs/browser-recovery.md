# 瀏覽器工作流程診斷與修正

此文件規範 AI 助手在已授權任務中遇到問題時，如何即時診斷、修正腳本、安全接續與回報。這是操作規範；本次文件更新沒有新增通用自動修復引擎、逐步日誌模組或自動控制權交接。個別工作流程仍須遵守自己的 failure policy、輸出契約及重試上限。

## 操作方向與網站分類

優先使用 CDP 執行已驗證流程，必要時評估 extension 輔助。穩定性及完整完成優先，速度其次。AI 工作瀏覽器與使用者日常瀏覽器分開使用。

| 網站類型 | 平常操作 | 故障時診斷 |
|---|---|---|
| 介面變動較頻繁，例如 ChatGPT、Gemini、NotebookLM | 執行前確認該步驟需要的介面與狀態；沿用仍有效的定位與成果驗證 | 依現場 DOM、框架與可見狀態確認是否改版；有證據才修改定位或流程 |
| 長期穩定，例如操作方的公文、財管系統 | 優先沿用已驗證固定腳本；做必要前置及成果檢查，不每次重新探查整套系統 | 先查登入、連線、資料、等待、彈窗、擴充功能及腳本實作；有介面變動證據才改定位 |

分類是操作方目前的維護經驗，不是網站永不改版的保證。遇到已確認的變動可更新分類；不能僅因逾時就認定改版。業務腳本留在各自專案，本 repo 提供共用流程。

## 修正程序

1. **定位失敗步驟**：保留原始錯誤、預期結果、最後已確認完成的步驟，以及必要的頁面／框架證據。停止無效的下游等待；輸出尚未確認時先檢查實際成果，不盲目重送。
2. **分類原因**：辨別工作階段／連線、伺服器或模型處理、資料／業務規則、頁面互動／等待、擴充功能干擾、Windows 系統視窗、介面契約變動或原因未明。頁面可見不代表伺服器處理完成；原始錯誤和推測分開記錄。
3. **選擇最小修正**：已授權範圍內的定位、框架、等待及操作方式可以當次修改。穩定系統優先修復實作卡點；頻繁變動服務也必須以現場證據支持修改。保留無關使用者變更，不順便重寫整套流程。
4. **確認接續點**：重新取得有效工作占用並核對原實例、精確分頁、頁面狀態及已完成操作。只重做已確認未完成、可安全重試的步驟。提交狀態不明時先回讀；無法回讀就停止，不能假設未提交。
5. **驗證結果**：依原任務契約核對姓名／條件、筆數、內容、原始檔格式、新鮮度及必要畫面。腳本退出成功、按鈕點過或暫存檔存在都不足以證明完整完成。
6. **回報並留下紀錄**：說明觀察到的原因、修改檔案、重試與人工協助、已完成與未完成成果、總耗時及驗證範圍。確認可重用的修正後更新對應 workflow 文件和 repo 操作紀錄。

已驗證送出的 AI 請求不因修正或切換分頁而自動重送；既有契約可能要求停止批次，通用修正程序不覆蓋這些規則。原因未明不算 CDP 能力不足，修正後重跑成功也不能反推已查明根因。

## 下載完成度

分開記錄三種結果：

- **頁面成果**：生成或報表已完成，畫面／內容符合需求。
- **原始檔取檔**：取得完整原始資料並通過格式、內容及新鮮度驗證。
- **瀏覽器原生下載**：需要此路徑的任務，必須完成另存等視窗、確認最終檔案；要求下載面板點擊開啟時，也要實際驗證該行為。

完整 PDF 暫存資料複製另存，只證明原始檔取檔。Chrome 若仍停在 Windows「另存新檔」，原生下載流程尚未完成。不能以暫存檔另存取代這項驗收，亦不能將產生成功與下載成功混成一個狀態。

工具逾時後先確認成果是否其實已完成，避免重複下載或重複提交。先檢查真正的下載位置、檔名與時間；保留原生下載處理，遵守 runbook 的下載接管限制。下載網址被擴充功能改寫時，記錄實際控制介面與干擾因素；受政策拒絕的操作不以其他介面繞過。

## extension 與系統視窗

目前沒有確認「CDP 無法完成、extension 卻能完成」的必要接手案例，自動接續保留為未驗證項目，暫不為假設案例開發通用交接功能。

需要人工安排接續時，先停止並斷開前一控制者，再核對原實例、精確分頁、任務狀態與有效租約；任務內控制權切換與任務結束釋放租約分別處理。不得讓兩個控制者同時操作同一實例。

Windows 另存等系統視窗可能超出瀏覽器控制工具範圍。先確認目前工具能力；若需 computer-use 或人工操作，將它記為額外控制方式或人工協助。工具不可用時保存成果與停點、停止控制並釋放占用，需要保留的頁面依工具規則交接。不能將這種混合完成算成純 extension 自主完成。

## 重試、停止與紀錄

既有工作流程有重試上限與升級程序時，沿用原契約；通用規範不新增或重設重試額度。沒有上限的舊流程先記錄最多兩次恢復嘗試，同一阻礙第三次出現仍無新證據則停止，保存失敗狀態並請求必要協助。不在停止後換一種工具重設計數。登入、驗證碼、權限、工具安全政策或不明業務規則屬獨立停點，依既有授權及工具規則處理。

故障紀錄至少包含：

| 欄位 | 內容 |
|---|---|
| 工作識別 | 任務、控制方式、網站分類、實例與精確目標的安全識別 |
| 步驟 | 入口條件、預期成果、失敗步驟、最後確認完成步驟 |
| 原因與證據 | 原始錯誤、原因分類、觀察證據、未確認的推測 |
| 修正 | 變更檔案、修正摘要、每次恢復的時間與結果 |
| 驗證 | 成果位置、格式／內容／筆數檢查、原生下載狀態、未完成部分 |
| 完成度 | 一次完成、恢復後完成、部分完成或未完成；額外工具及人工協助 |
| 時間 | 開始、失敗、恢復、驗證完成；總耗時含等待與重試，人工等待另列 |

這是後續工作與既有日誌擴充的紀錄要求，不宣稱所有現有腳本已產生上述欄位。私有成果、業務內容與完整診斷證據保留在 repo 外；可提交可重用修正與不含敏感內容的摘要，遵守 repo 既有資料規則。
